## Notes

* Fixture reset: `data/cities.json` is read-only during these tests; no reset is needed since `search_city` and `get_weather` only read fixture data and do not modify it.
* `get_weather` is read-only and does not modify fixture data, so no fixture reset is required before or after its test cases.
* To simulate offline/timeout for `TC-04`, `TC-08`, and `GW-05`, temporarily disconnect Wi-Fi or block the relevant Open-Meteo host, then run the case in Inspector.
* For `GW-05`, the internet connection was disabled and `get_weather` successfully returned local fallback data for Hebron.
* Confirmed from `weather-alerts.ts`: `get_weather_alerts` has a fixture fallback using `data/weather-alerts.json`.
* Before running `TC-05`, `TC-07`, and `TC-08`, use a real city name that exists in `data/cities.json` so the intended live or fixture path is exercised correctly.
* An unrecognized city in `get_weather_alerts` may be handled similarly to an API/fallback failure, so this behavior may be worth tracking separately as a future improvement.
* `TC-05` and `TC-07` were satisfied by the same Inspector run because the live request succeeded while returning an empty `alerts` array.
* All five `get_weather` manual test cases passed successfully in MCP Inspector.
